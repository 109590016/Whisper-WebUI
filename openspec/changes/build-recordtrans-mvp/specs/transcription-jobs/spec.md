# Spec Delta

## Purpose

提供可追蹤且可恢復的本機轉錄任務生命週期，避免長時間 GPU 工作因刷新或重啟失去狀態。

## ADDED Requirements

### Requirement: 持久化任務狀態
系統 SHALL 記錄等待、處理、完成、失敗與已中斷狀態，以及來源、attempt 與結果參照。

#### Scenario: 重新整理頁面
- **WHEN** 使用者在任務建立後重新整理頁面
- **THEN** 系統仍顯示任務目前狀態與既有結果

### Requirement: 單 GPU 排隊
系統 MUST 限制同一時間最多一個任務執行 GPU 推論，其他已接受任務保持等待狀態。

#### Scenario: 同時提交兩個任務
- **WHEN** 使用者在第一個任務處理期間提交第二個任務
- **THEN** 第一個任務處理且第二個任務等待，直到資源可用

### Requirement: 失敗與中斷可重試
系統 SHALL 允許從仍存在的永久來源重試失敗或已中斷任務，並以新的 attempt 保存結果。

#### Scenario: 服務重啟
- **WHEN** 系統啟動時發現先前仍為處理中的任務
- **THEN** 系統將其標記為已中斷並允許使用者重試

#### Scenario: 重試失敗任務
- **WHEN** 使用者重試且原始來源仍存在
- **THEN** 系統建立新的 attempt，保留先前紀錄並重新排隊

### Requirement: 可理解的進度與錯誤
系統 SHALL 顯示目前階段、已用時間與可採取行動的錯誤；在沒有可靠比例時不得捏造完成百分比。

#### Scenario: 轉錄進行中
- **WHEN** 任務正在處理且模型未提供可靠總進度
- **THEN** 系統顯示處理階段與已用時間，不顯示虛構百分比
